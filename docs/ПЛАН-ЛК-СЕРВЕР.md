28.10.2026. Владелец: «а ладно делай кабинет покупателя сразу» (раньше был долгом до сервера). Образец – Milovini:
сайт `milovini.deford.ru` + админка `admin.milovini.deford.ru`, выкладка `~/Sites/shop-modules/deploy/milovini/deploy.sh`,
сайт в режиме `PUBLIC_LOYALTY=api` (milovini-samara коммиты 94fba4f, e05931d, c1593ec, d5fde37), shop-modules ПЛАН-S7e.

## Решения

1. **Адреса стенда:** `alexkrown.deford.ru` (сайт + `/api`), `admin.alexkrown.deford.ru` (админка магазина shop-modules).
   DNS – A-записи на 45.12.72.227 через API reg.ru (~/.config/regru), как у Milovini. Стенд закрыт паролем стенда
   (basic auth, общий `~/.config/shop-stand/basic-auth`) и noindex – это и ответ владельцу «закрыть показ паролем».
   Боевой домен alex-krown.com – после «да» на карту адресов (public/karta) и решения по переносу.
2. **Сервер:** свой экземпляр `/opt/shop-alexkrown`, compose-проект `shop-ak`, сеть, база, бэкап (таймер 01:00 UTC),
   блоки Caddy `shop-ak-site` / `shop-ak-admin` – копия deploy/milovini с заменой имён. Письма с кодом – Unisender Go,
   на стенде – перехватчик `shop-stand-mail` (как у Milovini).
3. **Товары на сервере – позиция «товар + размер»** (`uid:размер`, цена размера; без размеров – `uid:`): так считают
   корзина и демо-движок (src/v1/loyalty.ts lineId). Импорт `catalog import --if-empty`; новые товары и цены после
   первой выкладки – ТЕХДОЛГ (у Milovini так же).
4. **Правила программы – один источник `src/data/v1/loyalty.json`** (вкладка «Бонусы» админки сайта, оферта раздел 11).
   В админке shop-modules экрана настроек программы нет, поэтому выкладка переводит loyalty.json в settings
   (bonus / tiers / orders) и отправляет, когда он изменился (хэш на сервере), а не один раз, как у Milovini.
5. **Частичное списание на сервере:** `points` (сколько баллов) в `/api/cart/quote` и `/api/orders`
   (apps/api/src/routes/shop.ts → quoteForCustomer / placeOrder), с тестами; без `points` – как сейчас («всё»). Фасад
   `createApiShop` передаёт `points`. Движок – пересобрать, скопировать в alex-krown/src/vendor.
6. **Сайт в режиме сервера** (`PUBLIC_LOYALTY=api`): `src/v1/loyalty.ts` – createApiShop на том же хосте; вход –
   галочка согласия передаётся в verify (`{ pdn: true }`); тексты без «демо»; оформление – заказ в базу через API
   (баллы удерживаются до оплаты в магазине), менеджеру в Telegram – «Баллами» и «К оплате», как у Milovini (d5fde37).
   Pages-показ остаётся демо в браузере (путь А) – один код, режим выбирается при сборке.
7. **Проверка:** тесты shop-modules (vitest), tsc обоих репо, deploy.sh сам проверяет снаружи пароль/noindex/API/CSP/
   админку; живой путь на стенде: вход по коду (перехватчик) → товар → заказ с частью баллов → заказ в админке →
   «оплачен» → «доставлен» → баллы доступны.
